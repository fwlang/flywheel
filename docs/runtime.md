# Runtime and ownership

LLVM values hold primitive numbers and booleans directly. Immutable UTF-8 strings, homogeneous arrays, class instances, JSON documents, and markup nodes are heap objects with atomic reference counts. Class and array slots and element children retain their referenced objects. Arrays and instances have shared identity; assigning an array aliases it, and mutations are visible through both variables. Strings have value semantics and concatenation allocates a new string.

Generated functions establish an ownership frame. Object locals and parameters have initialized owning roots. Object stores retain the incoming reference before releasing the previous one. Loads and field reads retain temporary references through the current statement, preserving left-to-right behavior even if a nested call replaces the original variable or field. Completed statements drain temporary references; conditions also drain temporaries before loop iterations. A `for` iterable has a hidden root and is evaluated exactly once. Returned objects are retained before the callee's frame is destroyed and adopted by the caller. All normal and early returns destroy the function's frame.

Local roots currently remain registered until function exit, even after their lexical scope ends; later executions of the same declaration replace its root. A loop does not accumulate one root per iteration. Earlier scope release, move optimization, borrowed-value analysis, stack allocation, and escape analysis remain unimplemented. Reference-count operations are atomic; this does not make mutable arrays or class fields safe for concurrent access. Parallel language execution is not enabled.

Strong reference cycles are not collected. `weak<T>` is not implemented, so the specification's weak back-link example cannot yet be validated. Avoid strong cycles in this checkpoint. Fatal runtime errors print a diagnostic and terminate with status 1; there is no catch/unwind path yet. The operating system reclaims resources on fatal termination. The implementation does not claim exception-safe ARC until typed exceptions and unwind cleanup are added.

Markup is constructed directly by compiled native calls. No XML parser is included in the runtime. HTML serialization escapes text and attributes; booleans omit false attributes. Entities in source text and static attribute segments are decoded at compile time and escaped once on rendering. The server calls native zero-argument functions and releases each returned tree after serialization.

Formatting an element or fragment uses the same `fw_render` path as explicit `html.render`. The serialized string is owned by the current temporary frame and released at the statement boundary. Formatting retains the existing ownership of the tree; printing a retained tree repeatedly remains valid, and temporary trees are released through normal ARC cleanup.
